## Design: "Deep Space 3D"

The hero, dividers, and footer are **hand-written animated SVGs committed to
this repo** (`assets/`). They use CSS/SMIL animations *inside* the SVG file, so
they animate when GitHub renders them via `<img>` — no external service, no
rate limits, no broken images. Animations include:

- **Hero** — moving 3D perspective grid (synthwave floor), floating isometric
  cubes, twinkling starfield, drifting glow orbs, pulsing neon horizon,
  gradient title with a periodic shine sweep, staggered fade-in tech chips.
- **Divider** — a neon light-beam that sweeps across a faint track.
- **Footer** — drifting aurora blobs, twinkling stars, pulsing neon top edge.

All three respect `prefers-reduced-motion` (animations pause for users who ask
for reduced motion).

## Why light/dark "switching" was removed

GitHub's `<picture> + prefers-color-scheme` trick follows the *viewer's*
theme/OS combination — you can't control it, and when the viewer's OS theme
and GitHub theme disagree it picks the "wrong" image. That is why it looked
broken. The new design is **theme-agnostic**: dark hero/footer cards look like
intentional design panels on both light and dark GitHub, and all stat widgets
use `theme=transparent` with mid-tone text that stays readable on both. The
only remaining `<picture>` swaps are the snake, the 3D chart, and the activity
graph, where both variants look fine either way.

## Activate the animations (one-time, 2 minutes)

The snake and 3D chart are **generated by GitHub Actions** — until the
workflows run once, those two images 404. Your last push did **not** create
the `output` branch, which means Actions is likely disabled on the repo:

1. Push this commit to `main`.
2. Open the repo → **Actions** tab. If you see a banner like *"Workflows
   aren't being run on this forked repository"* or an **"I understand my
   workflows, go ahead and enable them"** button — click enable.
3. Both workflows now also trigger **on every push to main**, so they should
   start immediately after enabling + pushing. If not, open each workflow →
   **Run workflow** (manual dispatch).
4. Verify: repo → branches → an `output` branch appears (snake), and a
   `profile-3d-contrib/` folder appears on `main` (3D chart). Refresh your
   profile. Both regenerate automatically every day.

## If the 3D chart shows a broken image

The action commits SVGs into `profile-3d-contrib/` on `main`. The README
references `profile-night-rainbow.svg` (dark) and `profile-season-animate.svg`
(light). After the first run, confirm those filenames exist in that folder —
if the action version generated different names, update the two URLs in the
"Contribution Universe" section.

## Notes

- **Trophies widget removed** — `github-profile-trophy.vercel.app` is
  frequently rate-limited and rendered as a broken image (as seen 2026-07-09).
- **Stats cards are self-hosted** — `github-readme-stats.vercel.app` returned
  a persistent HTTP 503 (verified 2026-07-09), so `scripts/generate_stats.py`
  now renders Deep-Space-styled overview + language cards from the GitHub API
  via `stats.yml` (on push + daily). The committed placeholders show em-dashes
  until the first workflow run overwrites them with real numbers.
- **BUET logo** is hotlinked from Wikipedia
  (`upload.wikimedia.org/wikipedia/en/d/da/BUET_LOGO.svg`). It is a fair-use
  university emblem — standard for indicating affiliation. If UW-BUET gives
  you an official program logo, swap that URL in.
- **Streak stats** uses `streak-stats.demolab.com` with its `transparent`
  theme (the old herokuapp instance is dead).
- Asset URLs in the README are absolute
  (`raw.githubusercontent.com/.../main/assets/...`) so they render on the
  profile page immediately after push.
